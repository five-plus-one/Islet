# Islet 产品与交互设计

更新：2026-10-07

## 产品目标

Islet 为个人与团队提供可靠的图片存储和分发工作台。核心路径为：上传图片 → 获取链接 → 整理到相册 → 查找与复用 → 回收与恢复。采用 Go、React 19、5plus1-ui、双端口与既有数据模型。

参考 GravityLink 的设计令牌、紧凑导航、独立工具栏、上下文详情、响应式布局和请求状态规范。以图片为主视觉，采用浅色中性底、海蓝色主操作、细边框和克制阴影。

## 信息架构

- 工作区：图片库（默认首页）、上传图片、相册、回收站、上传密钥。
- 管理：运行概览、存储策略、用户分组、用户管理、系统设置。
- 个人中心位于用户菜单；侧栏底部展示容量与账号入口。
- 普通用户只查询、编辑与恢复自己的图片。管理员的全站浏览必须显式选择；跨用户修改与彻底清理由超级管理员执行。
- 普通用户无法调用管理 API；上传密钥仅用于上传，不能访问管理或账号接口。

## 视觉与布局

- 桌面侧栏 232px，顶栏 64px；内容最大宽 1600px，24–32px 边距。
- 768px 以下侧栏为可关闭抽屉，工具栏自动换行；图片双列、管理列表允许在自身容器横向滚动，页面不横向溢出。
- 图片卡片统一比例，点击预览，复选框承担多选；名称、省略提示、尺寸与大小保持稳定位置。
- 图片详情使用右侧抽屉；预览、链接格式、文件信息与编辑在同一上下文内完成，关闭保留筛选与滚动位置。
- 全站统一按钮、表单、空态、加载、失败重试、禁用和提交中状态；键盘焦点清晰，操作有可访问名称。
- UI 使用中文任务语言。系统设置保留配置所必需的技术名称，普通用户流程呈现容量、格式、进度与下一步操作。

## 核心流程

### 上传

支持选择、拖拽、粘贴；选择相册及可用存储，展示单文件限制与剩余容量。文件加入独立任务队列，每项有等待、上传、完成、失败状态和真实传输进度。失败可重试；并发入口进入同一队列。成功后可按直链、Markdown、HTML、BBCode 复制单项或本次成功项目，或查看图库。离开页面需保留队列或明确提醒。

### 图库与相册

搜索、相册和格式组合筛选，筛选同步 URL；区分首次空库与无匹配结果。分页使用时间与 ID 组合游标，返回下一游标和是否还有记录；切换查询时过期响应不得覆盖当前结果。支持已选图片批量复制、移入相册和回收，逐项反馈失败。编辑使用表单副本，取消不会修改卡片；标签随记录初始化。相册入口直接进入对应筛选。创建与编辑相册具有独立的初始化逻辑。

### 回收站

所有用户可管理自己的回收站；超级管理员可管理全站。显示删除时间，支持恢复与逐项永久删除。永久删除必须先验证回收状态和所有权，存储失败时保留记录以便重试。回收不等于撤回浏览器或 CDN 已缓存的公开图片；确认文案说明链接影响。批量操作报告实际成功和失败数量。

### 上传密钥

名称、创建时间、最后使用、到期时间与状态清晰可见。创建时只展示一次凭证，复制成功后由用户主动关闭；撤销需要确认。PicGo 指南展示实际公开上传地址、POST、multipart/form-data、files 字段与 Authorization 请求头。

### 管理与账户

概览展示真实用量、上传趋势、待审核人数与分组分布；读取失败显示重试，不填充虚假零值。分组配额定义为每位成员的容量上限。系统设置分区呈现，保存有反馈；禁止关闭唯一可用登录方式。存储策略修改须保留已上传对象的可访问性，引用中的存储位置字段禁止随意迁移。登录支持本地账号，配置加载失败可重试。

超级管理员可创建本地用户，指定分组与初始密码；本地用户可在个人中心验证原密码后修改密码，修改后现有会话失效并重新登录。密码为 10–72 字节。上传与恢复使用用户行锁串行核算配额；图片解码限制像素数。

恢复与永久删除通过图片行锁协调，防止同一图片同时恢复和清除。存储写入采用仅创建语义，已有同名对象保持原有内容。

## 实施顺序与验收

1. 权限隔离与数据生命周期：管理角色限制、个人图库范围、上传相册归属、回收与永久删除、分页稳定性。
2. 设计系统与工作区：导航、登录、图库详情、批量操作、上传队列、相册、个人回收站。
3. 管理功能一致性：密钥、用量、分组、用户、存储、设置与加载恢复。
4. 验证：Go 构建与测试、前端类型与构建、Compose 校验、本地账号容器流程、真实浏览器桌面及手机操作。

发布验收覆盖未登录访问、用户隔离、管理越权、上传/预览/复制/编辑/取消/筛选/相册/回收/恢复/永久删除、失败重试、长文件名、空状态、窄屏布局。外部 OIDC 与真实云存储须在对应服务和凭据可用时进行专项验收。
